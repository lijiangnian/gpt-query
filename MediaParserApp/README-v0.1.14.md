# MediaParser v0.1.14 — 双模型转写、Gemini对照校对与断句

## 使用方法

在字幕路线选择“Gemini + Groq → Gemini校对”，保存两家Key，点击生成并确认双上传与额外文字调用。
默认仍是单Gemini路线，旧的单Gemini、单Groq选项均保留。API设置仍在页面最下方，默认收起。

流程：提取同一份音频一次 → Groq原稿 → Gemini原稿 → Gemini文字模型对照 → AI整合稿。
两份原稿分别保存SRT/TXT；整合稿和修改记录另存，不覆盖原稿。
页面可切换“Gemini原稿 / Groq原稿 / AI整合稿”，复制SRT/全文始终对应当前查看版本。
若两份原稿已成功、校对失败，显示部分完成并保留两份原稿，可点击“仅重试Gemini校对”，不重传音频。
若第二家转写失败，保留第一家已保存的原稿，不显示虚假的“整合成功”。

## 模型与额度

- Groq转写沿用可选的whisper-large-v3（默认）/whisper-large-v3-turbo。
- Gemini转写使用gemini-3.5-transcribe。
- 最终文本对照使用gemini-3.1-flash-lite，不用转写模型代替文字编辑模型。
- 校对阶段只发送两份文字，不重新听音频；没有搜索、外部工具或自动跨账号请求。
- 双模式需两家Key，消耗两份转写额度及Gemini文字额度，不是无限免费。
- Google当前价格页列出所选Flash-Lite的Free Tier；实际可用额度及账单以用户项目为准，App不自动开通账单。
- 文本按短块、每批最多650字符和40块处理，Gemini批次开始至少间隔约32秒。这是保守节流，不是项目额度保证。
- HTTP/配额/格式异常不盲目重复文字POST，不回退到其他收件服务。

依据：[Gemini结构化输出文档](https://ai.google.dev/gemini-api/docs/structured-output)、[Google价格页](https://ai.google.dev/gemini-api/docs/pricing)。

## 时间轴与断句

- Gemini原稿的字级时间是唯一时间基准；Groq只作文字参考，不混合两家的时间戳。
- AI只能返回原文连续片段和对应修订文字，不能返回新时间戳。
- App检查顺序与完整覆盖，确保无原文片段漏掉、重复或调序。
- 先按原稿标点、停顿、说话人和时长/长度边界构造短块，AI在块内校对或细分。
- 边界若落在原始单词内部，合并相邻建议，直到真实单词边界；不按字符数估算时间。
- 单路线的本地备用分段也改为到长度/时长界限时回看附近标点或停顿。
- 所有原始时间仍来自ASR。文字校对不能解决ASR本身听漏了、时间偏移或短对白时间过短的问题。

## 校对保护与局限

提示词适用于不同主题，没有写死猎豹、AE86等视频答案。
对数字、否定、删词或改动过大的建议保留原文、记录待核对项；模型自己标记不确定的词义修改也不直接采用。
结构、原文覆盖、时间映射等检查不通过时，整版不发布，原稿照常保留。
数字保护也可能阻止合理的车型拼写修正，需要人确认，这是有意保守的取舍。
两份ASR原稿一致不代表正确，文字AI仍会误改；“待复听”标记不保证找出所有错误。
两稿都没有的台词不会由模型凭空补入，参考稿独有台词也不会在缺少主稿时间锚点时插入SRT。
整合稿仍有待校对错误，不能称为人工校正版，也没有测得通用准确率。

## 原视频实测结果

视频为用户提供的228.276秒视频，无损抽取原始AAC音轨。
本轮真实请求Gemini转写；参考稿使用上一轮对同一原始音轨实际调用Groq Large V3得到的记录。
没有为重试校对重复上传音频，也没有从用户粘贴的无时间轴文本伪造SRT。
Gemini文字校对实际执行3批，成功轮耗时约84.44秒（含节流等待，不含前面的ASR/下载）。

最终解析器对这3个真实响应离线回放后：

- 输出84段，22处修改，6个待核对项。
- 每段开始/结束均对应原始Gemini word时间，没有新增估算边界。
- 部分“鬣豹→猎豹”“目的→陆地”等得到修正。
- 仍保留了“A 186”“为了捕猎长鬣豹…”等待确认内容，部分口头台词和“别猫”等错误仍存在。
- AI曾尝试删除“在我国的非洲草原上”里的“我国”；程序保留原话，避免按常识改掉原视频的梗。
- 第一次试验触发数字保护；第二次触发过长段落检查。修订输入短块与逐项保护后才得到有效整合稿；失败不被算作成功。
- 最终6项/22处以离线回放为准；现场调用日志中的7项/21处来自数字保护细化前的解析器。

这些是功能和单片效果证据，不是整体准确率、WER或多场景质量结论。
