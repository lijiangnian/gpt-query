# MediaParser v0.1.16：句级时间轴降级与校对独立重试

针对用户截图中的 Groq「字级时间戳乱序」和 Gemini 校对「HTTP 500 / high demand」。

## 调整

- Groq 字级时间数据无效时，改为检查同一响应里的服务端句级时间；合格才导出 SRT。没有排序、拉伸、截断或猜测时间。句级也无效时仍只保存文字，并说明两级检查失败原因。
- 句级 SRT 显示来源提示。校对时保留整句起止，模型拆成多行也不会据此猜出句内时间。截图和参考稿按真实句级时间选取。
- Gemini 校对请求接入已有的有界重试：只对明确返回的 429、500、502、503、504 重试，每批总计最多三次，遵守现有 Retry-After 处理及退避规则。网络超时和校对内容校验失败不自动重复提交。进度显示当前批次、错误码、等待与重试次数，不会自动切换其他服务。
- 校对失败后，主按钮直接变为「仅重试Gemini校对」，结果顶部也有入口。重试沿用两份原稿和已保留的截图，不重新提取或上传音频，不再次调用两路 ASR。新一轮校对有独立进度，旧失败状态不会覆盖新状态。
- 原稿、校对稿及修改记录分别保留；另有明确的「重新转写两路」入口。API Key 设置继续在底部默认折叠，115 功能没有加入。

## 验证

- 184 项字幕、网络与校对测试 + 24 项链接解析测试通过；包括校对真实 POST 处理边界的模拟 HTTP 500→500→200、持续繁忙、鉴权失败、Retry-After、超时不重发、取消及保留原稿测试。
- 回放此前保存的真实 Groq 响应：701 个字词锚点存在多处乱序，但 90 段服务端句级时间有效。新版恢复 90 段，并逐一核对起止时间与响应完全一致（按应用现有厘秒精度输出），全文未更改。这是历史响应回放，不是声称这次截图里的视频也已验证。
- Android APK 编译、版本、签名、INTERNET 唯一权限、无本地 Whisper 模型及交付包密钥检查在打包时验证。
- 本次真实 Gemini 校对调用结果另见随包 live-result.json，使用此前 25.833 秒视频保存的两份转写稿与 13 张截图，复用新版网络和校对核心，不重新调用 ASR。截图来自桌面 ffmpeg，不能替代 Android 端抽帧测试。

## 限制与使用

HTTP 500 来自服务端，客户端重试不能保证总能成功，也不代表 Key 无效。时间格式校验不能证明逐字对齐，AI 文稿和截图仍可能出错，需复听。

校对单独重试目前依赖当前结果页内存中的两份稿件和截图；退出、重启或切换结果会失去本次重试上下文。已经保存到 Download 的原稿不会删除。升级不能从旧版已丢弃的原始 API 时间数据恢复 Groq SRT；要得到新版句级降级结果，需在新版重新生成一次。

若长稿后续批次失败，自动重试仅重发失败批次；手动「仅重试校对」会重跑校对批次，仍不重跑 ASR，可能额外消耗校对额度。没有加入跨重启断点续传。

没有连接 Android 真机或模拟器，尚未验证手机按钮交互、MediaMetadataRetriever 抽帧及系统 Download 保存。此次没有直接重新运行截图中那条未复制出来的媒体链接。没有宣称模型普遍准确或上游永不报错。

与 v0.1.15 使用同一签名，可尝试覆盖安装；不需要先卸载。源代码位于 gpt-query 的 reliability-v0116 覆盖层，仓库更新 ZIP 含所有前序层及 v0116 工作流，未推送 Git 远端。
